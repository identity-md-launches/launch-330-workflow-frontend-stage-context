# Ember buyback and burn — frontend

Single-page static site for the Ember (EMBR) `BuybackBurnHook` on Sepolia. It shows the burned
total, the pending buyback ETH, whether a buyback can run now, a public **Run buyback** button,
the last 20 `Buyback` events, and a small swap panel for buying or selling EMBR through the
launch pool. There is no backend: reads go to public Sepolia RPCs, and transactions are signed
in the visitor's browser wallet.

Stack: Vite 8, React 19, TypeScript, viem. The production export is committed at the
repository-root `dist/` with a relative base, so it works from an IPFS gateway subpath or an
ENS name without server rewrites.

## Configuration: one source of truth

The app has **no hard-coded addresses, chain ID, ABIs or RPC URLs**. At startup it fetches
`./imd-deployment.json` (the deployment manifest next to `index.html`) and then the ABI files
it references, checking each ABI's canonical keccak against the attested `abiHash` before
anything is trusted. If the manifest or an ABI fails to load or verify, the page shows an
error and no transaction control is enabled.

| What | Where |
| --- | --- |
| Contract names, addresses, ABI paths and hashes | `public/imd-deployment.json` → `contracts[]` (copied to `dist/`) |
| Chain ID, name, public RPC URLs, explorer, native currency | `public/imd-deployment.json` → `network` (copied byte for byte from the vetted network table) |
| Uniswap v4 addresses used by quotes, approvals and swaps | `public/imd-deployment.json` → `network.uniswapV4` |
| ABI JSON (raw arrays from `docs/abi/`) | `public/abi/*.json` |
| Pool parameters from the launch manifest (fee 3000, tick spacing 60, native ETH paired), event scan start block, polling/slippage defaults | `src/config.ts` |

`src/config.ts` also reads the optional `VITE_WALLETCONNECT_PROJECT_ID` build variable. No
project ID is supplied for this deployment, so the app offers browser wallets only (EIP-6963
discovery with a `window.ethereum` fallback). A WalletConnect ID is a public identifier; no
private RPC keys or other credentials are used anywhere.

`dist/imd-deployment.json` is regenerated by `scripts/finalize-manifest.mjs` after every build.
It copies the identifiers, contract set and network block from `public/imd-deployment.json`,
re-verifies the ABI hashes and records the SHA-256 of every other exported file.

## Install, preview, rebuild

```sh
cd web
npm ci                # install pinned dependencies (package-lock.json)
npm run dev           # Vite dev server with the same manifest and ABIs
npm run typecheck     # tsc --noEmit
npm test              # vitest: unit + interaction tests with a mocked node and wallet
npm run build         # vite build → ../dist, then finalize dist/imd-deployment.json
npm run preview       # serve ../dist locally
npm run verify:manifest   # fail if dist/imd-deployment.json is stale
```

Commit `dist/` together with the source after any change. The publisher pins the committed
export without rebuilding it.

## How the page works

- **Reads** (`src/chain.ts`): `accruedEth`, `burnedTotal`, `lastBuybackBlock`, `MIN_BUYBACK`,
  `MAX_BUYBACK`, `FEE_BPS` on the hook, the burn address's EMBR balance, the pool's `slot0` and
  liquidity via the network's `stateView`, and the head block. Polled every 15 s and after
  each confirmed transaction. The pool key is native ETH / EMBR / 3000 / 60 / hook; the pool
  ID is `keccak256(abi.encode(key))`.
- **Eligibility**: `accruedEth >= MIN_BUYBACK` and no buyback in the current block. This is a
  snapshot, not a guarantee; the call is also simulated before the wallet is asked to sign.
- **Events** (`src/hooks/useBuybacks.ts`): `Buyback(poolId, ethSpent, tokensBurned)` logs
  filtered by hook address and pool ID, scanned backwards in ≤10 000-block windows from the
  head to the deployment block, then incrementally.
- **Wallet** (`src/wallet.ts`): `wallet_switchEthereumChain`; on 4902 or an equivalent
  "unknown chain" error, `wallet_addEthereumChain` with the manifest network, then switch
  again. A single "Switch to Sepolia" control appears while on the wrong chain.
- **Swap** (`src/swap.ts`): quotes via `quoteExactInputSingle` on the manifest quoter using
  `simulateContract` (never a transaction); swaps via the universal router's `execute` with
  command `0x10` and actions `0x060c0f`. Buying sends ETH as value; selling shows ERC-20 →
  Permit2 and Permit2 → router approvals as separate steps. `execute` is simulated first and
  the decoded revert reason is shown.
